# CommChain —— 数字通信系统模拟器

程序设计实践课程综合项目（C# 版）。以指导书**综合项目二「信号的调制与解调（文本到二进制）」的完整通信链路为骨架**，综合运用第一~第三阶段及综合项目一的特性，构建一个可交互演示的端到端数字通信系统模拟器。

- 语言/框架：C# / .NET（纯 BCL 实现，**零第三方依赖**）
- 交互方式：控制台菜单（每个模块可单独演示，另有端到端全链路一键模拟）
- 测试：xUnit 单元测试（含固定随机种子下的端到端可复现断言）

## 使用方法

### 1. 环境要求

- 任意安装 .NET SDK 的机器（macOS / Windows / Linux），目标框架 .NET 10
- 无任何第三方 NuGet 依赖（仅测试项目引用 xUnit），编译运行即开即用

### 2. 安装 .NET SDK

```bash
# macOS（推荐，Homebrew）
brew install dotnet

# 或从官网下载安装包：https://dotnet.microsoft.com/download
# Windows / Linux 均可使用官方安装器，安装完成后验证：
dotnet --version
```

### 3. 运行程序

```bash
# 在项目根目录（CommChain/）下执行
dotnet run --project src/CommChain.App
```

启动后出现主菜单，输入编号（1~8）选择演示项，输入 0 退出。

### 4. 运行全部单元测试

```bash
# 在项目根目录（CommChain/）下执行
dotnet test
```

预期 50+ 用例全部通过。测试使用固定随机种子（42），任何机器上结果一致、可复现。

### 5. 主菜单使用指南

| 编号 | 演示项 | 需要输入 | 重点观察的输出 |
|------|--------|----------|----------------|
| 1 | 霍夫曼编码演示 | 一段文本 | 字符频率统计 → 前缀码表 → 压缩率（定长 8bit/字符 vs 变长码）→ 解码还原验证 |
| 2 | 链表队列演示 | 无 | 手写链表的入队/出队过程、Count 变化、空队列出队异常被捕获（程序不崩溃） |
| 3 | CRC 校验演示 | 待传输字符串 | 发送端 CRC-8（0x07）与简易校验和 → 模拟篡改 → 接收端重算检出错误 |
| 4 | 汉明码纠错演示 | 4 位数据比特（如 1011）+ 翻转位置（1~7，0 为不翻转） | 7 位码字生成 → 校验子定位错误位 → 纠错后数据复原 |
| 5 | 网络拓扑演示 | 源/目的节点编号（0~7） | 邻接矩阵打印 → Dijkstra 最短路径 → Floyd 全源结果与 Dijkstra 互证 |
| 6 | ASK/FSK 调制演示 | 8 位比特（如 10110010） | 两种调制方式的 ASCII 波形图 → 加噪 → 解调无误码 |
| 7 | 数据包合并分流演示 | 数据包数量（1~100） | 随机多信源包生成 → 合并入队 → 按目的地 ID 分流到各输出队列 |
| 8 | 端到端完整链路模拟 | 文本 + 模式（1 简化 / 2 完整）+ 错误档位（0/1/2） | 九阶段全过程与链路统计表（压缩率/BER/纠错数/CRC 失败数/路由） |

### 6. 端到端演示建议顺序（菜单 8）

1. 先选**简化模式**（模式 1）：对应指导书综合项目二原始四函数链路（文本→二进制→ASK 电平→阈值解调→文本），验证基本链路；
2. 再选**完整模式**（模式 2）跑三档错误，对比链路行为：

| 档位 | 输入 | 预期现象 |
|------|------|----------|
| 0 无差错 | 任意文本 | 完整无损恢复，统计表错误数/纠错数/CRC 失败数全为 0 |
| 1 少量可纠 | 任意文本 | 信道引入少量单比特错误，汉明码全部纠正，文本无损恢复 |
| 2 高频超限 | 任意文本 | 部分 7bit 块双错，汉明纠错失效，CRC 校验失败丢帧，恢复文本与原文不一致（校验兜底演示） |

### 7. 常见问题

- **`dotnet` 命令找不到**：.NET SDK 未安装或未加入 PATH，参见第 2 步；macOS Homebrew 安装后重开终端再试。
- **运行报错找不到 `topology.txt`**：请从项目根目录执行 `dotnet run --project src/CommChain.App`（csproj 已配置拓扑文件随构建复制到输出目录，直接运行输出目录中的 CommChain.App.dll 亦可）。
- **中文显示乱码**：主程序入口已强制设置 `Console.OutputEncoding = UTF-8`，如仍乱码请将终端编码切为 UTF-8（如 Windows Terminal / VS Code 内置终端默认即可）。
- **修改拓扑后演示不生效**：菜单 5 与菜单 8 从 `data/topology.txt` 加载拓扑，修改后重新运行即可；文件格式：第一行节点数，之后每行 `u v weight`，支持 `#` 注释。

## 端到端完整链路（菜单 8 完整模式，9 阶段）

```
应用层    文本
   │ 阶段2  霍夫曼信源编码（第一阶段：频率统计→优先队列建树→前缀码）
表示层    压缩比特流 + META 帧（码表序列化 + 有效长度）
   │ 阶段3  组帧：帧头[type/source/dest/seq/长度] + 载荷 + CRC-8（第二阶段）
链路层    META 帧 + 若干 DATA 帧
   │ 阶段4  网络层：真实包与背景噪声包合并入队 → 按目的地分流（综合项目一）
网络层    → Dijkstra 最短路径路由（第三阶段：图 + 文件 I/O 拓扑）
   │ 阶段5  信道编码：汉明码(7,4)，每 4bit → 7bit（第二阶段）
物理层    帧比特流
   │ 阶段6  FSK/ASK 调制 → 信道加噪 + 按 BER 比特翻转（第三阶段/综合项目二）
信道      三档错误：0 无差错 / 1 少量可纠 / 2 高频超限
   │ 阶段7  解调 → 汉明纠错（定位并翻转错误位）→ 拆帧 + CRC 校验兜底
接收端    丢弃 CRC 失败帧与背景噪声包
   │ 阶段8  霍夫曼解码（按 META 帧恢复码表与有效长度）
信宿      恢复文本
   │ 阶段9  一致性验证 + 链路统计表（压缩率/BER/纠错数/CRC 失败数/路由）
```

### 三档错误模拟（对应报告测试用例）

| 档位 | 信道行为 | 预期结果 |
|------|----------|----------|
| 0 无差错 | BER=0，噪声=0 | 完整无损恢复 |
| 1 少量可纠 | 每帧至多 1 比特错误 | 汉明码 100% 纠正，无损恢复 |
| 2 高频超限 | 高频错误、不限帧内错误数 | 部分 7bit 块出现双错 → 汉明纠错后仍有错 → CRC 校验失败并丢帧（校验兜底演示） |

## 关键设计说明

1. **BitSequence 统一数据契约**：所有模块间以比特序列传递数据，从源头消除 string/byte[]/bool[] 混用的歧义。
2. **霍夫曼码表随帧传输**：码表序列化为定长自描述格式 `[条目数][字符:16][码长:8][码字]`，放入 META 帧首传；数据帧只传压缩比特流（补零至整字节，有效长度随 META 帧传输）。
3. **标准汉明(7,4) 码**：码字布局 `[p1 p2 d1 p3 d2 d3 d4]`，校验子 s3s2s1 直接编码错误位置（0=无错，1~7=出错位）。注：指导书参考实现中校验位/校验子公式存在笔误（如按原公式 s3 恒为 0），本项目采用教科书标准实现并附单元测试验证全部 16 种数据与 7 种单错场景。
4. **确定性演示**：随机数固定种子（42），同一输入每次运行输出完全一致，保证报告截图与测试结果可复现。
5. **层次清晰**：发送端 应用→表示→链路→网络→物理 分层与接收端逆序解耦，每层职责单一，便于扩展（如替换调制方式、增加交织等）。
